# Памятка для защиты SHIFT PC

## С чего начать показ

«Это многостраничный учебный каталог компьютерных комплектующих. В нём пять обязательных страниц и дополнительные страницы товаров, сравнения, доставки и результата формы. HTML задаёт структуру, общий CSS оформляет сайт, а JavaScript используется только для открытия и закрытия модального окна».

Порядок: главная → каталог → товар → характеристики → модальное окно → заявка → контакты → сравнение → README → CSS → история Git.

Важно говорить правду: модели вымышлены, фильтры статические, форма не отправляет реальный заказ, проект подготовлен с помощью Codex. Нужно понимать код и объяснять собственные изменения.

## 22 контрольных вопроса

1. **Зачем отдельный репозиторий для каждой КР?** Чтобы у работы были собственные файлы, история и ссылка для сдачи. Проекты не смешиваются.

2. **Чем многостраничный сайт отличается от одностраничного?** Здесь переход открывает другой HTML-файл. У SPA основной HTML загружается один раз, а содержимое меняет JavaScript. Одностраничный лендинг и SPA — не обязательно одно и то же.

3. **Какие страницы обязательны?** `index.html`, `catalog.html`, `product.html`, `order.html`, `contacts.html`.

4. **Зачем единая навигация?** Пользователь на любой странице понимает, как перейти в нужный раздел. В шапке одинаковые пункты; текущий раздел выделен.

5. **Для чего якоря?** Для перехода к участку страницы. В `href` после `#` указан ID целевого элемента.

6. **Почему важны семантические теги?** Они обозначают смысл содержимого для разработчика, браузера и вспомогательных технологий. `nav` — навигация, `article` — самостоятельный материал.

7. **Почему один main?** Он обозначает основное содержимое текущей страницы. Повторяющиеся шапка и подвал находятся снаружи.

8. **Для чего article?** Для самостоятельного фрагмента. Карточку товара можно понять отдельно от остальных карточек.

9. **Зачем таблица?** Для связанных данных по строкам и столбцам: характеристик и сравнения. `caption` даёт название, `thead` — заголовки, `tbody` — данные, `th` — заголовочная ячейка, `td` — обычная.

10. **Зачем форма заявки?** Чтобы пользователь указал товар и данные для связи. Здесь демонстрируется только интерфейс: `GET` передаёт поля в адрес страницы результата. Настоящего оформления нет.

11. **Чем CSS-модалка отличается от dialog?** CSS-модалка обычно имитируется блоком и `:target` или переключателем. `dialog.showModal()` открывает нативное модальное окно в верхнем слое браузера, блокирует взаимодействие с фоном и поддерживает Escape. У нас `close()` закрывает окно кнопкой.

12. **Зачем CSS-переменные?** Чтобы хранить повторяющиеся значения в одном месте. Цвет кнопок можно изменить одной переменной.

13. **Зачем hover и focus-visible?** `hover` показывает наведение мышью, `focus-visible` — видимый фокус, например при переходах клавишей Tab. Один не заменяет другой.

14. **Для чего Flexbox?** Для раскладки вдоль одной основной оси: меню, ряд кнопок, строка цены и ссылки. `gap` задаёт промежутки, `justify-content` распределяет место по главной оси, `align-items` выравнивает по поперечной.

15. **Для чего Grid?** Для управления строками и колонками. `repeat(3, minmax(0, 1fr))` создаёт три равные колонки; `1fr` — доля свободного места.

16. **Что такое БЭМ?** Соглашение об именах классов: блок, элемент, модификатор. Оно помогает понять структуру по названию класса.

17. **Чем блок отличается от элемента?** Блок самостоятельный (`product-card`), элемент — его часть (`product-card__title`).

18. **Чем элемент отличается от модификатора?** Элемент — часть блока; модификатор меняет вид или состояние блока/элемента. `site-nav__link--active` обозначает активную ссылку и используется вместе с `site-nav__link`.

19. **Почему не рекомендуется стилизовать через id?** ID должен быть уникальным и имеет высокую специфичность. Классы удобнее переиспользовать и переопределять. ID здесь нужны для якорей, формы и поиска диалога.

20. **Что должно быть в README?** Название, тема КР, описание, структура, технологии, запуск, страницы, доработки, ФИО и группа, настоящая ссылка GitHub Pages.

21. **Какие доработки выполнены?** Дополнительные страницы товаров, сравнение наборов, доставка, FAQ, схемы комплектующих, хлебные крошки, связанные товары, подсказки формы и улучшения доступности.

22. **Почему это улучшает проект?** Карточки ведут к своим товарам, сравнение помогает понять состав и цену, FAQ отвечает на вопросы, хлебные крошки помогают вернуться, подписи и фокус делают управление понятнее.

## Ещё несколько вопросов, которые могут задать

**Что делают name, id и for?** `id` обозначает элемент, `for` связывает подпись с полем, `name` — имя параметра при отправке формы.

**Почему телефон без пробелов?** `pattern="\+7[0-9]{10}"` требует знак плюс, цифру 7 и ещё десять цифр. Подсказка соответствует этому формату. Это проверка формата, не существования номера.

**Почему нет автоматического выбора товара?** Это потребовало бы дополнительной логики. В рамках КР товар выбирается вручную в `select`.

**Зачем z-index?** Для порядка наложения позиционированных элементов внутри соответствующих контекстов. Нативный модальный dialog попадает в отдельный верхний слой; он не зависит только от большого z-index.

**Почему шапка повторяется в файлах?** Проект статический, без шаблонизатора и сборщика. Общий CSS один; повторение HTML принято ради простоты.

**Что станет следующим шагом?** В последующих КР можно расширить адаптивность, добавить рабочие фильтры и корзину на JavaScript, затем перенести интерфейс в компоненты.
