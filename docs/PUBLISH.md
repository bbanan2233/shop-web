# Публикация и сдача

Репозиторий проекта: https://github.com/bbanan2233/shop-web. Исходники загружаются через ветку `feature/shift-pc` и Pull Request. Актуальный статус публикации смотрите в README. Ниже — справочная инструкция для переноса проекта или повторной настройки.

## Вариант с сохранением истории Git

В архиве есть папка `.git`: она содержит локальные коммиты подготовки проекта. Не создавайте новый Git-репозиторий поверх неё и не удаляйте историю без необходимости. Авторы начальных коммитов обозначены как Codex; последующие собственные изменения фиксируйте под своим именем.

1. Создайте на GitHub пустой публичный репозиторий `kr1-html-css-shop`, без автоматически добавляемого README и `.gitignore`.
2. Откройте терминал в распакованной папке проекта.
3. Настройте своё имя и почту для будущих коммитов:

```bash
git config user.name "Ваше имя"
git config user.email "Ваша почта GitHub или адрес noreply"
```

4. Подключите фактический адрес созданного репозитория и отправьте историю:

```bash
git remote add origin https://github.com/YOUR_LOGIN/kr1-html-css-shop.git
git push -u origin main
```

`YOUR_LOGIN` заменяется вашим GitHub-логином. Не публикуйте эту строку как готовую ссылку. При необходимости войдите в GitHub штатным способом Git или GitHub Desktop; пароль или токен в код проекта не записывайте.

## Включение GitHub Pages

В репозитории откройте **Settings → Pages**. В разделе **Build and deployment** выберите **Source → Deploy from a branch**, ветку **main**, папку **/(root)** и сохраните настройки. После успешной публикации скопируйте показанную GitHub ссылку.

Источник инструкции: [GitHub Docs — Configuring a publishing source](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

Публикуется корень проекта, где лежит `index.html`, а не папка `docs`. Папка `docs` в этом проекте содержит инструкции.

## Финальная доработка через ветку и Pull Request

После публикации и ручного просмотра внесите реальные исправления отдельной веткой:

```bash
git switch -c fix/final-review
```

Обновите README фактической ссылкой GitHub Pages и внесите найденные исправления. Затем:

```bash
git add .
git commit -m "docs: add published site URL and review fixes"
git push -u origin fix/final-review
```

На GitHub откройте Pull Request из `fix/final-review` в `main`, проверьте изменения и выполните слияние. Это покажет осмысленный цикл работы с Git из первой лекции.

## Что сдавать

- В СДО — ссылку на **репозиторий**, а не архив и не только сайт.
- В README — рабочую ссылку на **GitHub Pages**.
- На защите — страницы, HTML/CSS, обязательные приёмы, доработки и историю коммитов.

Не сдавайте работу до ручной проверки и добавления настоящей ссылки на опубликованный сайт.
